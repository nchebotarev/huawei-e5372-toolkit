# Известные ограничения

## AdBlock и память

После включения AdBlock в исходном разговоре наблюдались зависание и перезагрузка. Вероятная причина — нагрузка на память; журнала OOM и измерения пикового потребления нет. При сборе подтверждён список из 58 539 правил, около 1,6 МБ на диске. Постоянное состояние — Off; возможность включения сохранена с подписью `On (high memory usage)`.

## Доступ к панели

В watchdog нет ограничения bind на LAN IP и нет параметров HTTP-аутентификации. На устройстве не найден отдельный `httpd.conf` в каталоге панели. CGI запускаются административным процессом. `status.cgi` раскрывает WAN IP, Cell ID и статистику, `dns.cgi` меняет конфигурацию через GET без собственной проверки входа, метода и CSRF-токена.

Фактическая доступность из WAN зависит от штатного firewall и при сборе не проверялась. Панель следует считать административным интерфейсом доверенной локальной сети; публикация исходников не означает, что её можно открывать в интернет.

## TLS и проверка DoT

`GETDNS_AUTHENTICATION_NONE` отключает проверку сертификата. `tls_auth_name` в сгенерированном YAML не отменяет этот режим. `dotcheck.cgi` подтверждает лишь существующее TCP-соединение процесса Stubby на порт 853; он не доказывает подлинность сервера, успешность конкретного DNS-ответа или отсутствие иных путей DNS.

## Совместимость и DNS

- Только одно устройство было источником архива; другие модели и аппаратные модификации не испытаны.
- Адрес `192.168.8.1` задан в CGI и кнопке; смена LAN IP требует согласованных правок.
- Список DNS-профилей включает старые тестовые серверы. Все профили при архивировании не проверялись.
- `dns.cgi` и `dns_profile.sh` не имеют блокировки от одновременного применения нескольких запросов.
- При неудачном запуске custom Stubby нет автоматического отката. Наличие процесса считается успехом; полная проверка DNS выполняется отдельно.
- Штатный DNS-скрипт комментирует ограничения IPv6: используемый путь перенаправления IPv4 не является защитой от всех DNS-запросов IPv6 клиентов.
- Для профиля `operator` UI выключает AdBlock, но CLI может сохранить `adblock=1` без работающей блокировки.
- Названия и IP upstream в HTML продублированы вручную; могут расходиться с таблицей backend.

## Достоверность диагностики

- `firmware` в `status.cgi` — заданная вручную строка, а не динамическая версия прошивки.
- LTE band в панели — декодированная маска разрешённых диапазонов; текущая обслуживающая частота не определяется.
- `status.cgi` формирует JSON через `printf` без общего экранирования всех строк Huawei API. Необычные кавычки/переносы в значениях могут сделать JSON некорректным.
- При запуске `dotcheck.cgi` фоновый DNS-запрос не получает собственного тайм-аута от скрипта.
- Диагностический режим опрашивает состояние каждые 3 секунды; каждый запрос обращается к API и AT. Для обычной работы предусмотрено 60 секунд.

## Watchdog и журналирование

После более трёх выходов httpd в 600-секундном окне watchdog завершается. Его собственный лог не ограничен; HTTP-лог обрезается только между перезапусками. Проверки запуска через `ps | grep` основаны на совпадении имени и не заменяют PID-файл.

## Что ещё не проверено

Повторная установка, откат, reboot в рамках текущего сбора, точный аппаратный суффикс, Fast Boot/USB и внешняя доступность панели. Версия прошивки и модель подтверждены AT-командами, но не device API. По уточнению пользователя, в экранном меню выбран Remote access = Web + Telnet и ADB выключен. Работающий процесс `adbd` не позволяет установить доступность ADB по USB без отдельной проверки. Ранее в разговоре восстановление после reboot считалось работающим. История первоначальной прошивки недоступна; этот архив её не заменяет.
