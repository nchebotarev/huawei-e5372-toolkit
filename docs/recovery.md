# Восстановление и откат

Это восстановление пользовательской панели и DNS на уже работающей прошивке. Восстановление загрузчика, разделов и базовой прошивки здесь не описано: точная аппаратная модификация и прежние прошивочные пакеты пока не подтверждены.

Команды ниже составлены по исходникам. Во время архивирования остановка сервисов и откат не выполнялись.

## DNS перестал работать после смены профиля

При доступной консоли верните DNS оператора и выключите пожелание AdBlock:

```sh
/data/userdata/zoid-dns/dns_profile.sh apply operator 0
/data/userdata/zoid-dns/dns_profile.sh status
```

Если пользовательский скрипт повреждён, используйте штатный механизм и приведите сохранённое состояние в соответствие:

```sh
/etc/dns_over_tls.sh 0
echo 0 > /data/userdata/dns_over_tls
echo operator > /data/userdata/zoid-dns/profile
echo 0 > /data/userdata/zoid-dns/adblock
```

После этого проверьте DNS с клиента. Запись файлов без остановки стека не отключает работающие процессы или правила перенаправления. Если сам штатный скрипт повреждён, требуется отдельное восстановление базовой прошивки/её файлов.

## Отключение AdBlock при сохранении DoT

Выберите известный рабочий профиль с аргументом `0`, например:

```sh
/data/userdata/zoid-dns/dns_profile.sh apply yandex 0
```

Список блокировки на диске удалять не требуется. Если устройство недоступно, эти команды выполнить нельзя; дождитесь доступного административного интерфейса или используйте проверенную процедуру восстановления именно своей модификации устройства.

## Панель не открывается

Сначала проверьте штатный WebUI, процессы, порт и логи по [диагностике](diagnostics.md). Watchdog может завершиться после частых падений httpd. Если его действительно нет, можно запустить `/data/userdata/statusweb/watchdog.sh &` вручную.

Для остановки перед обновлением сначала остановите именно пользовательский watchdog, затем его HTTP-сервер. Команды выбирают процессы по конкретным путям:

```sh
for pid in $(ps | busybox awk '/[s]tatusweb\/watchdog.sh/ {print $1}'); do kill "$pid"; done
for pid in $(ps | busybox awk '/[h]ttpd/ && /statusweb/ {print $1}'); do kill "$pid"; done
```

Сверьте выбранные строки `ps` перед выполнением. Если оставить watchdog работающим, он снова поднимет httpd.

## Полный откат пользовательских доработок

1. Подготовьте локальные резервные копии и прочитайте обе пользовательские секции в `/app/bin/oled_hijack/autorun.sh`.
2. Верните DNS оператора или другой заранее выбранный базовый режим; для удаления custom DNS используйте `operator 0`.
3. Удалите из autorun только секции, сохранённые в `integration/oled-autorun.append.sh`. Если восстановление DNS ещё выполняется, найдите процесс `dns_autorun.sh` и дождитесь завершения либо остановите именно его перед дальнейшими действиями.
4. Остановите пользовательский watchdog и httpd.
5. Восстановите пользовательские каталоги из резервных копий либо оставьте их на диске как неактивный архив. Не удаляйте системные компоненты Stubby/dnsmasq.
6. Восстановите страницу WebUI из резервной копии либо удалите только кастомную кнопку по [инструкции](webui-button.md).
7. Проверьте синтаксис autorun, штатный интерфейс и DNS; затем при необходимости проверьте загрузку после перезапуска.

Восстановление `stubby.original.yml` не откатывает весь DNS-стек: это шаблон пользовательского генератора, а не полный образ исходного состояния устройства.
