# DNS-профили

## Сохранённое состояние

При сборе: `profile=yandex`, `adblock=0`, `/data/userdata/dns_over_tls=1`. Stubby запущен с `/data/userdata/zoid-dns/stubby.yml`, dnsmasq — с `/etc/dnsmasq.conf`. TLS-соединение Stubby подтверждено через `dotcheck.cgi`.

## Таблица

Источник истины для backend — [`src/zoid-dns/profiles`](../src/zoid-dns/profiles). Формат каждой строки:

```text
id|Название|IPv4_1,IPv4_2|tls_auth_name
```

В архиве 16 DoT-профилей: Yandex, Quad9, Cloudflare, Google, AdGuard, Sinodun, GetDNS, Censurfridns, Restena, CMRG, SecureDNS.eu, BitwiseShift, DNSPrivacy.at, Bitgeek, Neutopia, Applied Privacy. Семнадцатый вариант `operator` отключает пользовательский DNS-стек и возвращает DNS оператора.

Адреса и названия сохранены как на роутере. Доступность всех профилей на дату архивирования не проверялась. Особенно старые тестовые upstream нельзя считать актуальными только из-за наличия в меню.

`stock` используется как служебное значение при отсутствии сохранённого профиля: autorun ничего не восстанавливает. В таблице его нет; команда `apply stock 0` не поддерживается.

## Как применяется профиль

Для DoT-профиля `dns_profile.sh`:

1. Ищет профиль в таблице и формирует `stubby.yml` из шаблона.
2. Вызывает `/etc/dns_over_tls.sh 0`, останавливает Stubby и dnsmasq.
3. Записывает режим `1` или `2`, запускает штатный DNS-стек и правила перенаправления.
4. Останавливает штатный Stubby и запускает его с пользовательским YAML.
5. Через проверку списка процессов подтверждает наличие Stubby, затем сохраняет профиль и настройку AdBlock.

Это проверка наличия процесса, а не успешного DNS-разрешения. Ошибка не запускает автоматический откат. Переключение может временно прерывать DNS для всех клиентов.

При `operator` стек выключается, режим становится `0`. Интерфейс выключает выбор AdBlock для этого профиля, однако CLI допускает сохранение `adblock=1` при фактически отключённом пользовательском DNS; используйте `operator 0`.

## Команды

Чтение:

```sh
/data/userdata/zoid-dns/dns_profile.sh status
```

Намеренная смена профиля без AdBlock:

```sh
/data/userdata/zoid-dns/dns_profile.sh apply yandex 0
```

Возврат к DNS оператора:

```sh
/data/userdata/zoid-dns/dns_profile.sh apply operator 0
```

При загрузке `dns_autorun.sh` ждёт появления dnsmasq или Stubby до 60 секунд, затем ещё 5 секунд и применяет сохранённый профиль. Для `operator` ожидание может занять полную минуту, если штатный стек не запущен.

## TLS

Архивный YAML использует только `GETDNS_TRANSPORT_TLS`, слушает `127.0.0.1@5354`, idle timeout — 20 секунд. Настройка `tls_authentication: GETDNS_AUTHENTICATION_NONE` отключает проверку сертификата, даже если указан `tls_auth_name`. Это шифрованный транспорт без подтверждения подлинности upstream.

`dotcheck.cgi` создаёт DNS-запрос `zoid-<timestamp>.google.com`, затем до 10 секунд ищет `ESTABLISHED`-соединение процесса Stubby на `:853`. Проверка не доказывает подлинность сервера, не связывает соединение с конкретным запросом и не проверяет отсутствие иных DNS-путей для клиентов.

## Изменение таблицы

Чтобы добавить профиль, нужно согласованно изменить `profiles`, HTML `<select>`, `dnsProfileName()` и `dnsUpstreams()` в `status.html`. Таблица отображения IP в интерфейсе задана вручную и может отстать от backend.

Не редактируйте только сгенерированный `stubby.yml`: следующее переключение перезапишет его. Настройки транспорта и TLS задаются в `stubby.original.yml`; upstream — в `profiles`. В архиве изменения таких настроек не сделаны.
